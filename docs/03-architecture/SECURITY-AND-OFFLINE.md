# Security and offline design

Authentication uses Laravel's password hashing and session controls. Authorization is server-side: role gates protect administration and sensitive casework, while controllers additionally enforce case-worker assignment coverage. User interface visibility is not a security boundary. Writes are validated and business workflow transitions are allow-listed. Audit rows record key actions, including document and synchronization events.

Offline records are restricted to minimal work items. The active field queue and case pack are AES-GCM encrypted in IndexedDB using a device-only passphrase; the obsolete plaintext IndexedDB queue has been removed. The browser never receives the full registry: field workers receive only their authorized cases and the pack excludes documents and unnecessary contact details. A regular report-intake form can save an encrypted local intake when connectivity disappears, and the Offline Workspace can queue permitted notes and monitoring updates.

On reconnect, the client posts each operation to Laravel; the server authenticates, authorizes, validates, performs idempotency checks, records the canonical result, and rejects stale case-version writes as conflicts. The queue tracks pending, failed, synced, and conflict states. Attachments and administration remain online-only. Encryption reduces local exposure but does not replace the operational controls that still need owner approval: managed-device enrollment, passphrase handling, logout/retention cleanup, lost-device response, pack duration/size, and access revocation.
