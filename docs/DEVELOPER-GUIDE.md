# Developer guide

How the code is organised, how to run and test it, and the conventions that
keep it secure and consistent. Read [AGENTS.md](../AGENTS.md) first.

## 1. Architecture

| Layer | Where | Notes |
|---|---|---|
| Routes | `routes/web.php`, `routes/auth.php` | Every case route is under `auth`; case ids are numeric only (`AppServiceProvider::NUMERIC_ROUTE_PARAMETERS`). Writes use `throttle:sensitive-write`. |
| Controllers | `app/Http/Controllers` | Thin: authorise first, then validate, then call a service. Every write records an audit row. |
| Services | `app/Services` | Business rules: `CaseAccessScope` (who can see a case), `RolePermissions`, `CaseLifecyclePolicy`, `CaseReports`, `SmartSuggestions`, `ReferralTracking`, `RecordsGovernance`, `IdentityIntegrity`, `MdtGrantScope`. |
| Audit | `app/Support/AuditLog.php` | `AuditLog::insert([...])` adds the IP address and timestamps. Store ids and codes, never narratives. PostgreSQL trigger makes `audit_logs` append-only. |
| Security headers | `app/Http/Middleware/SecurityHeaders.php` | CSP with nonce; applied to pages and error responses. |
| Pages | `resources/js/Pages` | Inertia pages, one per screen. |
| Components | `resources/js/Components` | Case panels (`Case*Panel.vue`), reports (`Components/Reports`), UI kit (`Components/UI`). |
| Utilities | `resources/js/utils` | `philippineTime.ts` (all date display; stored times are UTC), `reportFormat.ts`, `caseSearch.ts`, `caseDisplay.ts`. |
| Offline | `resources/js/Offline`, `public/sw.js` | Field mode: AES-GCM encrypted IndexedDB, service worker with cached field app; sync through `OfflineSyncController`. |
| Help content | `resources/js/data/helpGuides.ts` | In-app Help & guides. Update it when a screen changes. |

Roles: `system_admin`, `social_worker`, `fo_user`, `cpu_member`. Permissions
per role are in `RolePermissions`. The effective list is in the ICTMS system
documentation (access control list).

## 2. Conventions

- Dates: never use `new Date(string)` for stored values. Use `formatPh(value, preset)` from `utils/philippineTime.ts`.
- Confirmations: forms are confirmed by `SubmissionConfirmation.vue`. Set `data-confirm-title`, `data-confirm-message`, `data-confirm-action` and, for destructive actions, `data-confirm-tone="danger"` on the form.
- Labels: sentence case for buttons, headings and page titles ("Submit for review", not "Submit for Review").
- Accessibility: tap targets at least 44 px (`min-h-11`), visible focus, text contrast at least `text-slate-500` on white and `text-slate-600` on grey.
- Mobile first: check every screen at 360, 390 and 768 px. Tables need a card layout on phones.
- Reports: built only in `CaseReports.php`. Sensitive domains (health, reproductive health, mental health) are withheld. Names print as initials unless the user chooses to show them.
- Text: plain ASCII hyphen-minus only.

## 3. Tests

| Suite | Command | What it covers |
|---|---|---|
| PHP (SQLite) | `composer test` | Feature and unit tests (about 440) |
| PHP (PostgreSQL) | `composer test:pgsql` | Same suite on PostgreSQL; needs database `kalinga_test` |
| Front end | `npm run test:frontend` | Offline sync, history encryption, Philippine time, case search |
| Browser | `npx playwright test -c playwright.review.config.ts` | 240 tests at 360, 390, 768 and 1440 px, including accessibility checks (axe) |
| Style | `composer lint` | Laravel Pint |
| Security | `composer security` | `scripts/security-check.sh`: audits, debug flags, `v-html`, public files |

Tests that create database triggers use `tests/Support/SyntheticTrigger.php`
so they run on both SQLite and PostgreSQL. New browser specs must be added to
`testMatch` in `playwright.foundation.config.ts`.

## 4. Database

- Migrations in `database/migrations`; never edit an applied migration.
- Data dictionary: `docs/04-database/DATA-DICTIONARY.md` and `data-dictionary.csv`, generated by `scripts/generate_data_dictionary.py` (usage in the script header). Add new tables to `TABLES` and `GROUPS` in the script.
- Diagrams: `docs/diagrams/*.dot` (render with Graphviz `dot -Tpng`).

## 5. Adding a feature checklist

Connect group/private messaging uses the shared CoordinationAccess eligibility
query. Direct-message endpoints live in CoordinationDirectMessageController;
never reuse group message queries for private history. See
[Connect delivery and reproduction](implementation/CONNECT-MESSAGING-2026-10-23.md)
for pair authorization, migration, demo scope repair, tests and known limits.

1. Permission in `RolePermissions` and a server-side check in the controller.
2. Route under `auth`, numeric id pattern, throttle for writes.
3. Audit row for every write (ids and codes only).
4. Feature test, including a test that an outside role gets 403.
5. Mobile layout checked at 360 px; Help & guides updated.
6. Update the user manual and the ICTMS documentation if the process changed.
