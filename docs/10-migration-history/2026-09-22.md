# 2026-09-22 migration decisions

The local application moved from SQLite verification to the separate PostgreSQL `kalinga_is` database. Existing `kalinga` and `kalinga_test` databases were deliberately excluded. Sheets-like records are modeled as normalized relational data with foreign keys, audit records, soft-delete controls and unique case/report identifiers.

Assessment saves use a version field to detect stale concurrent updates. Case plans contain independently tracked interventions. Offline operation IDs are UUID idempotency keys, allowing Laravel to accept a queued action once without silently duplicating it.

The `offline_version` field on cases provides server-side stale-write detection for queued notes and monitoring visits. A queued action whose base version differs from the current case version is retained as a conflict rather than applied. New self-registered accounts default to the read-only `viewer` role; role-to-permission mappings are seeded in `permission_role` and elevation is an audited administrator action.

The `migration/` workspace now includes a source-field mapping and a read-only `kalinga:validate-legacy-csv` command. It validates the approved copied CSV export shape without writing to `kalinga_is`; a write import remains deliberately deferred until an approved source-export and reconciliation plan exist.
